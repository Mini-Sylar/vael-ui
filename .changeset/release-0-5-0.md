## Upgrading

- **`motionCss` is now `motion` (breaking)**: on every component, on `ConfigProvider`, and in the options of `useCollapse`, `useSortable` and `useSortableGroup`. It works the same way: `:motion="false"` turns off the built-in animation. Find and replace `motion-css` and `motionCss` with `motion`.

- **`beforeClose` is a guard (breaking)**: it decides whether to close, and no longer runs your exit. Return `true` to close, `false` to stay open, or a promise of either, like `() => confirmAction(…).result`. The `(done) => …` form is gone. While it decides, the overlay holds still. To animate a close, use `motion` (below).

  ```ts
  // Before
  beforeClose: (done) => gsap.to(panel, { opacity: 0, onComplete: done })
  // After
  motion: {
    leave: ({ panel }) => gsap.to(panel, { opacity: 0 })
  }
  ```

- **List events are gone (breaking)**: `chip-enter`/`chip-leave` (Select, Combobox), `item-enter`/`item-leave` (CommandPalette, FileUpload, Timeline), `card-enter`/`card-leave` (Toaster), `row-enter`/`row-leave` (DataTable) and `action-enter`/`action-leave` (SpeedDial). Pass `enter` and `leave` hooks in `motion` instead: each gets the item by name (`{ toast }`, `{ row }`, `{ item }`, `{ action }`) and waits for the animation you return, so there's no `done()`. Chips live under `motion.chips` and CommandPalette's rows under `motion.items`, because the top level moves the panel. Timeline's hooks get the step's `marker`, `connector`, `previousConnector`, `content` and `opposite`, which replaces the removed `TimelineItemParts` type.
- **`force-mount` is for keeping content mounted**: it no longer switches animation over to you. With it, vael-ui leaves the element's motion alone; for your own animation, use `motion` hooks.
- **`motion="false"` covers the panel too**: on Select, Combobox, CascadeSelect, DatePicker, TreeSelect and CommandPalette, `false` now opens and closes the panel at once as well.
- **Message**: no longer shrinks while `beforeClose` decides. It leaves once the guard says yes.

Three components render different DOM. Their props, slots and events are unchanged, but a selector or a test that reaches inside them may need updating.

- **Button (breaking if you colour buttons)**: the box is now its own layer, `.ui-button::before`, and the contents sit in `.ui-button-inner`. A `background` or `border` you set on the button element paints under that layer, so it disappears on hover for ghost and outline buttons, and always for primary, secondary and danger. Set the button's variables instead:

  ```css
  /* Before */
  .my-button {
    background: #18181b;
    border-color: #3f3f46;
  }
  /* After */
  .my-button {
    --ui-button-bg: #18181b;
    --ui-button-border: #3f3f46;
  }
  ```

  From an unlayered stylesheet, such as Vue's scoped styles, your variables override the variant's own, hover included. For a dashed or dotted border, style the layer: `.my-button::before { border-style: dashed }`. To read a button's colour from code, read it from `::before`.

- **Sortable**: the root is now a `div` (`.ui-sortable`) with the `<ul>` inside it as `.ui-sortable-list`. Your class and a parent's scoped styles now reach the root.
- **Tooltip, TooltipHost**: the label sits in a `.ui-tooltip-content` span, and the box is drawn by `.ui-tooltip-panel::before`. `data-traveling` and `data-morphing` replace `data-sizing-locked`.
- **Lists' hover backgrounds**: rows in Select, Combobox, CommandPalette, Menu, Tree, TreeSelect, MenuList, DataTable, Pagination, Tabs, SelectButton, Toolbar and Calendar no longer paint their own hover or focus background. One `.ui-indicator` element slides behind them instead. If you restyled the hover with a selector such as `.ui-menu-item:hover { background: … }`, set `--ui-indicator-bg` instead, or your colour paints over the highlight. DataTable's striped and selected rows are now see-through tints, so the highlight shows under them; they look the same over the table's surface.
- **`--ui-indicator-bg`** is no longer set on `:root`. The highlight reads it with `var(--ui-muted)` as the fallback, so a panel that changes `--ui-muted` recolours its highlight too. If your own CSS uses `var(--ui-indicator-bg)`, add that fallback.
- **Stepper**: a step you can't reach yet is now a disabled button instead of a `div`, so its circle stays the same element as you move through the steps and its colour transitions. It looks the same; screen readers announce it as unavailable.

## The motion system

Every animated component now takes one `motion` prop, and every animation runs on one engine: CSS transitions and Web Animations on `transform` and `opacity`, loaded in small pieces as a page needs them.

- **`motion`**: `false` turns a component's motion off. An object changes it: values for each part (`{ initial: { panel: { opacity: 0, y: 8 } } }`, `exit`; a plain number is px, or degrees for `rotate`), timing (`{ spring: { damping, response } }`, or `duration` and `easing`), or `enter` and `leave` hooks. Each component exports its own type, such as `DialogMotion`, `SelectMotion` or `ToasterMotion`, so parts autocomplete.
- **Your own library**: a hook returns whatever GSAP, motion's `animate()` or `element.animate()` returns, or a promise, and the component waits for it. Closing mid-open or reopening mid-close stops it (`kill`, `stop` or `cancel`) and aborts `signal`. Hooks are skipped under reduced motion unless you set `reducedMotion: 'run'`.
- **Lists**: Toaster, Timeline, FileUpload, SpeedDial, DataTable rows, CommandPalette `items` and the Select family's `chips` stagger new items (`stagger`), lift a leaving item out so the rest close the gap (`leaving: 'pop'`, or `'hold'` to keep the gap until it's gone), and slide the others into place. Give `initial` or `exit` as a function and it gets `{ index, count }` of the items coming or going together, so a close can run last to first. `appear: true` also brings in the items already there when the list mounts, such as each time a CommandPalette opens, but never on hydration.
- **Overlays**: `morph: 'trigger'` grows an overlay out of the element that opened it and back into it: Dialog, Drawer, BottomSheet, Popover, Menu, Tooltip, Tour and the Select family's panels. On Dialog, Drawer and BottomSheet, `initial` also moves the inner parts (`title`, `body`, `footer` and the rest), and `linked` moves other elements with the overlay, such as the page receding behind a drawer, following a sheet's drag. `surface` draws a shape layer behind a Popover for gooey effects, `exitOrder: 'reverse'` closes children first, and `resize: false` stops a panel easing to new content sizes. While its width eases, text keeps the line breaks it lands with.
- **Your own engine**: a style's `engine` plays overlays' parts, list items and your targets through your library. It gets the element, `from` and `to` in vael-ui's names (`x`, `y`, `scale`, `opacity`), and the timing with the spring behind it, and returns what your library returns. States, swaps and `linked` stay on the built-in engine.
- **`ConfigProvider`'s `motion` style**: set the motion for a whole app, by role (`overlay`, `list`, `reveal`, `press`, `content`) or by component (`dialog`, `toaster`, `select`). A component's own `motion` wins. `presets` names looks for `v-animate`, such as `v-animate="'rise'"`, anywhere inside the provider. `parseMotionStyle` checks a style loaded from JSON.
- **`v-animate`**: animate your own elements. `v-animate="{ initial: { opacity: 0, y: 8 } }"` plays when the element appears, and when Vue removes it the element leaves back the way it came; `exit: false` turns that off. `.size` eases an element to its content's size, `layout: true` slides it when the layout moves it, `layoutId` carries an element between two places (a card into a dialog), with `layout: 'position'` keeping its size on the way so text never stretches, `replay` plays it again when the value changes (`appear: false` plays it only then), and `when: 'visible'` waits until it scrolls into view. `animate` is a look the element holds and moves to whenever it changes, from wherever it is: `animate: { rotate: open ? 180 : 0 }`. With keyframe arrays, `progress` (0 to 1) holds them at that point instead, so a swipe or a scroll scrubs them, and with a `spring` they follow it a beat behind. `v-animate:name` hands an element to the nearest component, which plays it with its own motion.
- **Every component can animate in**: `initial` on any component's parts plays when it mounts, never on hydration, such as `<Separator :motion="{ initial: { root: { scale: '0 1' } } }" />`. Repeated parts, like Rating's stars or a Stepper's steps, come in one after another with `stagger`, and `replay` plays the entrance again without remounting, such as a burst on a five-star rating; `appear: false` keeps it for replays only.
- **`motion` on every component**: each has its own type (`SwitchMotion`, `ProgressMotion`, …) for its parts and states, so a style can shake every invalid field or lift every pressed card. An array is a set of keyframes: `times` places them, `easing` eases each step (or a list gives each step its own, such as a rise and then a bounce), and `repeat` (with `repeatType: 'reverse'`) plays them again, or forever while the state is on. A part that comes many times plays its states one element at a time: a Stepper's `current`, `completed` and `upcoming` steps, each Dock item's hover and press, and `selected` each time one is picked, and OtpInput's new `cell` part, whose values can use each one's `index`. Switch, Checkbox and Radio add `unchecked`, so turning one off can play too. A `spring`, or a `duration` and `easing`, on one component retimes its own transitions: a Switch's release, a Progress fill, an AnimatedNumber's roll. Indicators in Tabs, SelectButton, MenuList, Pagination and Toolbar take a `spring`, and a `move` hook animates them yourself. On Tabs, Pagination and SelectButton, `stretch` lets the trailing edge follow on its own spring, a beat behind, so the pill stretches as it travels (`true`, or `{ trail, delay }`), and `squash` starts each move flattened, such as `0.82`; Pagination's page numbers change colour exactly where the pill is. Breadcrumb and AvatarGroup animate crumbs and avatars that come and go. A Toaster's `states` play when a toast changes variant, such as a promise toast landing on `error`. `false` holds a Loader still and stops a Skeleton pulsing.
- **Server rendering**: a `v-animate` appearance is written into the server HTML as CSS, so it plays before any script loads and doesn't play again on hydration. An overlay that is open on load shows as it is. The Nuxt module registers `v-animate` for you.
- **Your own components**: `useMotion` gives a component of yours the same `motion` prop behaviour: it follows the app's style, comes and goes, and its targets join it. In tests, `await settled()` waits until nothing vael-ui started is still animating.
- **Out of the way**: nothing animates in a hidden tab, a view coming back from `KeepAlive` doesn't replay, at most 24 elements appear together unless you time them with `delay` or `stagger` (the rest show without animating), and rows recycled while a list scrolls don't animate.
- **Development**: an overlay, and a component of yours using `useMotion`, carries `data-motion` on its root, naming where its motion came from, and each open and close shows up as a measure in the DevTools Performance panel. A part with its own CSS transition on a property the motion animates gets a warning.

## New

- **Editable**: text that becomes an input when you click it, for renaming in place, and saves on Enter or blur. `activation-mode` sets what starts editing, `submit-mode` sets what saves, and `v-model:editing` controls it. The `#edit` slot swaps in any control (a Textarea saves on Cmd or Ctrl+Enter), `#actions` adds save and cancel buttons, and `start`, `submit` and `cancel` are exposed. A control in `#edit` with its own panel, such as a DatePicker, keeps the edit open while you use the panel.
- **AnimatedNumber**: a number whose changed digits roll to their new value. `format` takes any `Intl.NumberFormat` options (currency, percent, compact), and the locale follows `ConfigProvider`, numbering system included. A digit that appears or disappears fades while the number makes room. Screen readers hear the formatted value. `InputNumber` takes `animated` to roll its value the same way when it changes from the steppers, the arrow keys or your code; typing shows plain text. Tune the roll with `--ui-duration-number` and `--ui-ease-number`; `motion="false"` swaps digits without rolling.
- **AnimatedText**: swaps a label or status for new text: the new text rises 4px into place as the old one fades a third faster, and the box eases to the new width, so nothing beside it jumps. 150 ms, no blur. Tune it with `--ui-duration-text` and `--ui-ease-text`; `motion="false"` swaps at once for your own animation on the exposed `el`.
- **Input**: `animated` crossfades a placeholder that changes, even while the field is focused and empty, and a value your code sets while you're away from the field. What you type never animates. The `#display` slot draws the text yourself, for a fancy input: vael-ui places it exactly over the input's own text and scrolls it with a long value, while the real input keeps the caret, selection, autofill and screen reader text. An element in it with `pointer-events: auto` can take hover, say for a tooltip on a mention. Textarea has the same slot, following its wrapping and scroll, and PasswordInput, Combobox (the typed text, after any chips) and InputNumber pass it through.
- **Select, CascadeSelect, TreeSelect**: the selected label crossfades to a new choice, and a trigger sized to its content eases to the new width. `motion="false"` swaps it at once.
- **Button**: `hold` asks for a press and hold before a destructive action: a fill sweeps across while you hold, and `@click` fires when it completes. Letting go early snaps it back. `true` holds for 1200 ms, a number sets the time, Space and Enter hold too, and screen readers hear the new `button.hold` message ("Press and hold to confirm", key `uiKit.button.hold`) as the button's description, alongside any `aria-describedby` of your own. `holding` is exposed, and `holdProgress` (0 to 1) reaches the default slot, the component and CSS as `--ui-hold-progress`, so a label can change partway through.
- **InputNumber**: `scrub` lets you drag sideways on a field you're not typing in to change the value, one step per 4 px (or the number you pass) and ten with Shift. A click without a drag still focuses the field.
- **useColorScheme**: `setMode(mode, { from: event })` spreads the new scheme in a circle from the click, an element or a point, with a View Transition. Browsers without one, and reduced motion, switch at once.
- **useHaptic**: haptic feedback on phones that offer it. `selection()` is the lightest tick, `impact('light' | 'medium' | 'heavy')` a bump, `notification('success' | 'warning' | 'error')` a short pattern, `vibrate(pattern)` your own, and `intensity` scales them; `isSupported` says whether the device plays them. It works outside components too. `HapticImpact`, `HapticNotification`, `HapticOptions` and `UseHapticReturn` type it.
- **ConfigProvider `haptics`**: `true`, or `{ intensity }`, turns on vael-ui's own haptics, each fitted to its moment: a tick when a Switch flips, a light bump when a swiped row snaps or a pull passes the refresh point, a firmer one when a Sortable row lands, the heaviest when a held Button completes. `false` silences every `useHaptic` call inside too, yours included, for a "turn off haptics" setting. Unset, yours play and vael-ui's stay silent.
- **Switch**: drag the thumb. It follows the pointer, the track flips as it passes halfway, and it lands on the side you release it past; a tap still toggles. `dragging` is exposed and the root carries `data-dragging`.
- **One spring for everything**: `ConfigProvider`'s `:motion="{ spring: { damping, response } }"` puts drawers, sheets, toasts, AnimatedNumber and the sliding indicators on one spring. Crossfades such as AnimatedText keep their own quick timing. Damping below 1 overshoots, and binding it to refs retunes the app live. `indicator` still sets the indicators on their own. `springEasing` turns a spring into the CSS `linear()` curve and settle time behind it, in the shape `element.animate()` takes, so your own animations can use it too.
- **Dialog**: `origin="trigger"` zooms the panel out of the element that opened it, and back into it on close, on the drawer curve, so `ConfigProvider`'s spring carries it. Centred dialogs only; reduced motion keeps a fade.
- **ColorPicker**: a swatch that opens a picker with a saturation and brightness plane, a hue slider, a hex field, optional presets and an eyedropper where the browser supports one. The plane works with arrow keys, `v-model:open` controls the panel, and `name` submits the hex value with a form. Customise it with the `#trigger` and `#preset` slots, `show-eye-dropper` and `--ui-color-picker-radius`.
- **Progress**: `value` also takes segments (`{ value, label?, variant?, color? }`) that stack into one bar with a legend, for a storage breakdown or a budget. `value-text` sets `aria-valuetext`. `type="circle"` draws a ring, with the default slot in the middle for the percentage, and `sweep` turns it into a gauge: `180` is a half-ring, `270` a speedometer. Stacked segments make a donut. The ARIA attributes moved from the root to the track; `data-state` stays on the root.
- **Loader**: `type` picks the animation: `ring`, `dots`, `bars`, `comet` or `dither`. Each is pure CSS in a 1em square that follows the text color, so swapping one never moves a layout. Button's new `loader-type` picks one for its loading state, and `ConfigProvider`'s `loader-type` sets it for every spinner inside, including Button, list loading rows, loading toasts and PullToRefresh. All three also take your own component, or a render function such as `() => h(MySpinner, { speed: 2 })`, drawn in the same 1em box. `LoaderSource` types it.
- **Toaster**: `container` keeps a toaster's stack inside an element instead of the viewport, so a panel or a demo frame can show its own toasts. `teleportTo` also accepts an element.
- **OtpInput**: `variant="field"` draws one box around the whole code, and `placeholder` marks each empty cell. The active cell's ring is now one element, `ringEl`, that glides from cell to cell carrying the caret, and follows `ConfigProvider`'s `indicator`, springs included. It sits in `.ui-otp-cells` after the cells.
- **useNumberFormat**: returns `formatOptions`, the `Intl.NumberFormat` options it builds, so you can hand the same format to AnimatedNumber.
- **CommandPalette**: a `#footer` slot for key hints or a status line, which receives the highlighted `activeItem` and the `query`. `activeItem` is also exposed, so your own shortcuts can act on the highlighted row.
- **Textarea**: each side of the bottom action strip lines its contents up in one row, so a counter, an icon and a button align without extra markup.
- **Animation hooks**: Editable, ColorPicker and Progress accept `motion="false"` and expose their elements for your own animations: `previewEl`, `inputEl`, `swatchEl`, `panelEl`, `areaEl`, `thumbEl`, `fillEl` and `fillEls`.
- **Sliding highlight on every list**: the hover and keyboard highlight glides between rows in Select, Combobox, CommandPalette, Menu (and so ContextMenu, SplitButton and CascadeSelect), Tree, TreeSelect, MenuList, DataTable, Pagination, Tabs, SelectButton, Toolbar and Calendar. Keyboard focus always moves it, even with the pointer resting in the list. A move of more than 3 rows (typing to jump, Home, End, a new search) lands at once, and touch never shows it. It moves with `translate`, which the compositor animates, and writes straight to its element, so hovering never re-renders the list, even a DataTable or a long sidebar; a fast sweep glides after the pointer instead of jumping. Each component exposes it as `highlightEl`; `indicatorEl` stays the name for a selection indicator, and MenuList now exposes its current-page one. With `motion="false"` it moves at once, for an animation of your own. Crossing a group label or a separator keeps it on the last row, and it glides on from there.
- **ConfigProvider `indicator`**: sets how every sliding indicator inside moves, the hover highlight and the selection in Tabs, SelectButton and MenuList alike: `'glide'` (the default), `'instant'`, or a spring such as `{ damping: 0.5, response: 0.35 }`, where damping below 1 overshoots. A spring writes to the element on each frame, so nothing re-renders. `motion="false"` still makes them instant. `IndicatorMode` and `IndicatorSpring` type it, and `useTabIndicator` and `useHoverIndicator` take the same `indicator` option.
- **useHoverIndicator**: the composable behind that highlight, for your own lists. Mark the rows with `itemSelector`, put an element with the `ui-indicator` class in the list, and bind the `style` it returns. `motion: false` hands the movement to you; the docs show a highlight driven by `createSpring` that overshoots and stretches. `group` hands the highlight between neighbouring lists, so moving from one into the next glides across instead of fading out and in. MenuList and Tree do this on their own, for two nav groups or an explorer's sections.
- **useTabIndicator**: `scroller` for an indicator inside a list that scrolls, `matchCross` to match each row on the other axis too, `maxGlide` to jump instead of gliding over long moves, `motion: false` to move at once, and `position: 'translate'` to move it on the compositor. It returns `update()`, which re-measures once before the next paint however often you call it, and writes to `indicatorEl` directly when you pass one.
- **Slider, Knob, Dial**: a `change` event fires with the final value when you release or press a key, like a native range input; `v-model` still updates on every move.
- **BottomSheet**: setting the exposed `activeSnap` moves the sheet to that snap point.
- **SplitButton**: `unified` joins the action and its menu button into one surface, without the thin line between them.
- **Tree, TreeSelect**: `scroll-fade`, on by default, fades the list's edges while there's more to scroll. With `sticky-scroll`, only the bottom fades, so pinned rows stay solid.
- **Tokens**: `--ui-duration-drawer-exit`, `--ui-duration-stagger`, and for the highlight `--ui-duration-indicator` (120 ms), `--ui-duration-indicator-wide` (200 ms, for the wide rows of MenuList, Tree and DataTable), `--ui-ease-indicator` and `--ui-indicator-bg`. `ConfigProvider`'s `motion="false"` zeroes the two durations along with the rest. AnimatedNumber and AnimatedText add `--ui-duration-number`, `--ui-ease-number`, `--ui-duration-text` and `--ui-ease-text`.

## Motion

Every built-in animation now follows the same rules: it stays under 300 ms (drawers, a dialog grown from its trigger and AnimatedNumber's roll take longer, since they travel further), eases out when entering and leaving, closes faster than it opens, and under reduced motion keeps its fade but drops its movement.

- **Popover, Menu, Tooltip**: panels grow from the exact centre of their trigger, even after flipping or shifting to stay on screen, instead of from the nearest corner.
- **Button**: pressing no longer makes the label or icon flinch. The box and the contents scale together, and sizes snap to whole pixels at any root font size. At a 16 px root no size changes; at 14 px, the medium button grows from 31.5 px to 32 px.
- **Tooltip**: text no longer jitters, blurs or shifts, including on Windows. Moving between triggers glides from wherever the tooltip is, follows a target that is still moving (a magnifying Dock item), and resizes smoothly when its content changes.
- **Tree, TreeSelect**: folders open and close with a spring, and the rows below move with them, with no overlap or jitter on tall folders. Clicking again mid-way reverses the motion. Keyboard navigation, search and trees over 150 visible rows still change instantly. TreeSelect's panel grows with the tree, and an opening folder no longer shifts the scroll position.
- **Sortable**: rows spring into place everywhere: back into their own slot when released over it, between lists in a group, and into new slots when your data re-sorts after a drop. A dragged row takes its slot from its centre, not the pointer, and stays above the other rows the whole time. While rows settle, the root has `data-settling` and `isSettling` is exposed.
- **Calendar, DatePicker**: the month label resizes smoothly, and grids switching months or years no longer overlap or get clipped at the sides.
- **Collapsible, Accordion**: content that grows while a panel opens is no longer clipped, and panels ease out.
- **Message**: grows and shrinks with its fade, so the content below moves instead of jumping.
- **Select, CascadeSelect**: removing the last chip collapses it smoothly, and a trigger sized to its content eases to the placeholder's width.
- **Dock**: sliding a finger along the dock magnifies it, and tapping an item makes it bounce. Item tooltips open above the magnified item. `v-tooltip` takes a `sideOffset`, a number or a function.
- **Tour**: the callout travels with the spotlight between steps, including to a step on the other side of its target. Its `motion` (`duration` and `easing`, or `spring`) times that glide, and the spotlight exposes the cutout as `--ui-tour-cutout-x`, `-y`, `-width`, `-height` and `-radius`, for a ring of your own that follows it. A tour that's open when the page loads glides on its first step change too.
- **Tour**, **Popover**, **Tooltip**: asked for `left` or `right` with no room on either side (a full-width card on a phone), the panel goes below or above instead of being cut off.
- **Switch, Checkbox, Radio**: press feedback.
- **Slider**: a value set from your code, like a reset or a preset, glides the thumb and fill there, on the same timing as AnimatedNumber, so a ConfigProvider spring retunes it. Keys and a press on the track glide there too, while a drag follows the pointer at once. `motion: false` turns the glide off.
- **Drawers, BottomSheet**: close in 350 ms instead of 500 ms.
- **Chevrons**: in Select, Combobox, TreeSelect, SplitButton, CascadeSelect, DataTable and Accordion, they turn in step with their panel.
- **DataTable**: expansion rows that grow after opening are no longer clipped.
- **Tree**: in single selection, the selected row's tint slides from the previous selection, and fades in when it's more than 4 rows away.
- **Clear buttons** in Select, Combobox, CascadeSelect and TreeSelect: the button fades and shrinks where it is. In a fixed-width trigger the value area widens under it; in one sized to its content the trigger closes up. Leaving fades a quarter faster than appearing, on a plain ease-out, so the fade is visible.
- **Smaller changes**: Stepper checks and clear buttons scale in from 0.9 instead of 0.5. Under reduced motion, Skeleton pulses slower, OtpInput's caret blinks slower and Stepper keeps its colour fade. A keyboard-focused Tree row shows an inset ring.

## Fixes

- **Pressing at the edge**: a control that shrinks while pressed (close buttons, steppers, chip removers, menu items, interactive Cards and 25 more) keeps its full box clickable, so a press released near its edge no longer gets lost. Clickable DataTable rows no longer shrink on press; the hover highlight is their feedback.
- **Springs**: a spring stays smooth and never overshoots when the page drops to 30fps, where a snappy one could jitter or fly off before.
- **Field**: a page full of fields no longer restyles long lists on every hover. Field now learns whether its control has a frame from the control itself instead of a costly `:has()` selector.
- **OtpInput**: typing fast no longer snaps the gliding ring backwards; only the caret blink restarts.
- **Right to left**: the sliding selection in Tabs, SelectButton, MenuList and Pagination lands on the selected item instead of measuring from the wrong edge, and Switch's thumb starts on the right and travels left.
- **Smaller bundles**: Input, InputNumber, Select, CascadeSelect and TreeSelect load AnimatedText and AnimatedNumber after mount, showing the same text until they arrive, so a page that only renders fields doesn't ship the animation code up front.
- **Reduced motion**: every component reads one shared `prefers-reduced-motion` query instead of creating a new one on each check.
- **BottomSheet**: dragging is smooth on phones, and nothing behind the sheet scrolls while you drag. Pulling a raised sheet back down returns it to rest instead of closing it. When a phone's toolbars or keyboard appear, the sheet stays on its snap point. `scroll-fade`, on by default, fades the content's edges while there is more to scroll, and the first control's focus ring is no longer clipped.
- **CommandPalette**: on Android, the list filters as you type instead of waiting for the space bar, and the keyboard's action key picks the highlighted match. Moving up through a grouped list no longer hides the highlighted row under its group heading.
- **Dialog, Drawer, BottomSheet, CommandPalette**: with a classic scrollbar, as on Windows, a closing panel no longer jumps sideways. The page stays scroll-locked until the exit animation ends, so the scrollbar comes back after the panel is gone.
- **useColorScheme**: `resolvedMode` matches `initial` from the first render, so server-rendered HTML no longer starts in the system scheme.
- **Accordion, Collapsible**: a panel no longer hops by a fraction of a pixel as it finishes opening. It opens to its exact height instead of a rounded one.
- **Pagination**: hovering the current page no longer covers it with the hover background.
- **Radio, Checkbox, Switch**: at a fractional pixel ratio (Windows display scaling, or browser zoom) the dot, tick and thumb no longer shift when you press them. Each stays on its own compositor layer. Tables over 150 rendered rows and trees over 150 visible rows make their checkboxes static instead, with no press and no layer, so scrolling stays cheap; a virtualized table keeps them, since it renders only the rows on screen.
- **SelectButton**: the selection glides to a new choice. It used to jump, because the first measurement turned its transition off for good.
- **SpeedDial**: the trigger's plus sits in the middle of the button instead of a pixel above it, and the press no longer looks like a jitter.
- **`vael-ui/style.css`**: the full stylesheet now includes AvatarGroup, Breadcrumb, CommandPalette, PasswordInput, Rating, ScrollArea, Sortable, Stepper, Timeline and Tour, and the shared clear-button, tick and indicator styles. Before, an app importing the full stylesheet instead of each component's own CSS rendered those unstyled.
- **Resizable**: End no longer sizes a panel to `Infinity` when it has no `max`; it does nothing there.
- **useFileDrop, FileUpload**: dragging selected text or a link no longer lights the drop zone, and turning `disabled` on mid-drag clears the drag-over state instead of leaving it stuck.
- **moveTreeNode**: a move that fails leaves the data untouched; it used to leave an empty `children` array on the target.
- **useTabs**: object items each find their own tab; they used to share the first one, so focus jumped there.
- **Tooltip**: `open-change` reasons are typed as the close reasons that actually fire, without the `'hover'` and `'focus-visible'` that never did.
- **Forced colors**: in Windows high contrast, the sliding highlight shows as a `Highlight` outline, since the mode removes backgrounds.
- **Calendar, DatePicker**: clicking a disabled day from the previous or next month no longer moves to that month.
- **ColorPicker**: on Windows, the panel no longer scrolls sideways, and the eyedropper is the same height as the hex field.
- **Combobox**: the phone keyboard's action key picks the highlighted match. It sets `enterkeyhint="enter"`, which you can override.
- **Touch screens**: hover styles no longer stick after a tap, and pressed rows show a background instead. Two taps in a row on a stepper or a calendar arrow count as two presses instead of zooming the page on iOS.
- **Sortable**: `preview-mode="clone"` floats a copy from the start of every drag, not only once it leaves its list. The original is the placeholder: within its list it moves to where the row will land, so the list shows the result before you drop, and it stays in its list until the drop when the copy is over another; and it carries `data-sortable-source` (hidden by default; style it to show it dimmed or outlined). On drop the copy flies into the row's slot above every list and follows the row if the list re-sorts while it lands, and the placeholder fades out as it arrives (in place, when the row moved to another list).
- **Sortable**: lists make real room for a row. A list grows smoothly for a row hovering it from another list and closes again when it leaves; at the drop the row takes that room without a jump, and the list it left closes up instead of snapping. In a list that scrolls, the room lets autoscroll reach a gap at its end, and holding the row past the list's top or bottom keeps it scrolling that way. New `restrict-to-list` keeps the dragged row inside the part of the list it's over, so it never hangs past a fixed-height column (off by default). Autoscroll stops at the list's last row instead of chasing a dragged row into empty space (and jumping back on drop), and never scrolls a list sideways. A drop keeps the list where you scrolled it (scroll anchoring is off on `.ui-sortable`), a row dropped below the fold is scrolled into view, and a real row dropped into another list lands above every list, as a clone does.
- **Tooltip**: after a long press on Android, the next tap on the trigger works.
- **Text fields on phones**: PasswordInput, Combobox, CommandPalette and the Select, CascadeSelect and Tree filters no longer autocapitalise or autocorrect what you type. ColorPicker's hex field and Editable show “Done” on the keyboard.
- **PasswordInput**: `autocomplete` defaults to `new-password` when the field shows requirements, so phones suggest a strong password, and to `current-password` otherwise, so saved passwords fill in.
- **InputNumber**: on phones, a field that allows negative numbers opens the full keyboard, because iPhone number pads have no minus key. A whole-number field that can't go negative opens a digits-only keypad.
- **Safe areas**: in apps that use `viewport-fit=cover`, Toaster, BottomSheet and full-height drawers keep clear of the notch and the home indicator.
- **Dialog**: scrolling to the end of a long dialog no longer scrolls the page behind it.
- **DataTable**: changing page no longer flashes the table. The old page's rows stayed for two frames, doubling its height, and then every new row faded in. The new page now shows at once, and a removed row leaves the layout at once, so the rows below slide up.
- **Dock**: with `magnify` off, moving over the dock no longer clears the transforms your own animation sets on its items.
- **v-draggable**: a decorative child marked `aria-hidden`, such as Tabs' sliding highlight, is no longer counted as a row. It shifted every row by one, so a drag moved the wrong item.
- **v-draggable**: grabbing a row while the last drop is still landing no longer leaves a row stuck off its slot.
- **PasswordInput**: Edge no longer adds its own reveal button. Only `revealable` shows one.
- **Dialog**, **Drawer**, **BottomSheet**: a closing one lets taps through while it animates out, so reaching for a button (or a dock) right after closing no longer takes two taps.
